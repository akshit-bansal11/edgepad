# Golden frames for Edgepad protocol v1.
#
# Both test suites (android/ in Kotlin, windows/ in C#) read this file. For every
# line they encode the fields and must get exactly these bytes, then decode the
# bytes and must get exactly these fields. That is what stops the two sides from
# drifting apart: a change to one codec without the other fails a test.
#
# Format:  NAME field field ... = hex bytes
# All multi-byte integers are little-endian. The first byte is the frame type;
# the payload length is fixed per type, except TEXT, whose second header byte is
# the length of the UTF-8 text that follows (at most 255 bytes).

# PAD_STATE buttons lt rt lx ly rx ry — the whole controller in one 12-byte payload, laid out exactly like
# Windows' XINPUT_GAMEPAD so the laptop copies it rather than translating it. Triggers are 0..255; sticks are
# -32768..32767, positive up and right. The signed lines below are the ones that matter: every i16 here is
# written low byte first, so -32768 is 0x8000 -> "00 80", 32767 is 0x7fff -> "ff 7f", and -1 is "ff ff".
# Neutral: nothing held, sticks centred, triggers released. Twelve zero bytes.
PAD_STATE 0 0 0 0 0 0 0 = 23 00 00 00 00 00 00 00 00 00 00 00 00
# Both sticks pushed fully down-left. -32768 is the one value a sign-extension bug cannot fake its way past.
PAD_STATE 0 0 0 -32768 -32768 -32768 -32768 = 23 00 00 00 00 00 80 00 80 00 80 00 80
# Both sticks pushed fully up-right. 32767, one short of the negative limit's magnitude, as XInput reports it.
PAD_STATE 0 0 0 32767 32767 32767 32767 = 23 00 00 00 00 ff 7f ff 7f ff 7f ff 7f
# Both triggers buried. They are u8, not i16: 255 must stay 255 and not arrive as -1.
PAD_STATE 0 255 255 0 0 0 0 = 23 00 00 ff ff 00 00 00 00 00 00 00 00
# A, B, START and DPAD_UP held at once: 0x1000 | 0x2000 | 0x0010 | 0x0001 = 0x3011 = 12305. Sticks and
# triggers mixed so no two fields share a value and a transposed pair would be caught rather than cancel out.
PAD_STATE 12305 32 200 -1 1 256 -256 = 23 11 30 20 c8 ff ff 01 00 00 01 00 ff
# Every button XInput defines, held at once: 0xffff without the unused 0x0800 is 0xf7ff = 63487. The top bit
# is Y, which is where reading the mask as a signed short instead of a u16 turns a held button into nonsense.
PAD_STATE 63487 0 0 0 0 0 0 = 23 ff f7 00 00 00 00 00 00 00 00 00 00
